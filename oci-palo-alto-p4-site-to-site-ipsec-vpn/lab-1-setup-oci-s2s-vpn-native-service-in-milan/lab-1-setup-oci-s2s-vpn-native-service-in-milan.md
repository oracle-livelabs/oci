# Setup Site-to-Site VPN in Milan Region (OCI Native Service in Milan)

## Introduction

This lab prepares OCI Milan as a stand-in for a customer remote site. In a real deployment, that site would more commonly be an on-premises network or another cloud environment; Milan’s OCI-native Site-to-Site VPN is used here only as a convenient demonstration peer for the Palo Alto firewall in Frankfurt. If you already have another suitable remote VPN site, you can skip this lab and use it instead.

If your goal is only to learn how to establish an OCI native Site-to-Site IPSec VPN, you can complete this lab independently, without completing the other workshop labs.

Estimated time: 25 minutes

### Objectives

In this lab, you will:
- Configure the Milan VCN, DRG, and route tables, and enable ECMP on the DRG route table.
- Create the Customer-Premises Equipment (CPE) object for the Palo Alto firewall.
- Create the OCI IPSec connection and collect its tunnel information for the Palo Alto configuration.

## Task 2: Create Customer-Premises Equipment (CPE)

In this task, you create the **Customer-Premises Equipment (CPE)** object in OCI for the remote VPN endpoint (on-premises or another cloud environment). The CPE provides the public IP address of the Palo Alto VM-Series firewall in Frankfurt, which OCI uses to establish the IPSec tunnels. You will use this CPE object to create the Site-to-Site VPN connection in the next task.

1. Click on the **hamburger menu** in the top left corner.
2. Click on **Networking**.
3. Click on **Customer-premises equipment**.

    ![Open CPE service](images/task-2-open-cpe-service.png)

    - Click on the **Create CPE** button.

    ![Open CPE creation](images/task-2-open-cpe-creation.png)

<!-- -->

1. Specify a **Name** for the CPE.
2. Specify the **public IP address** for PA untrusted interface in Frankfurt. The Public IP will depend on the setup you have:
    - **Single instance:** Public IP of the Untrust interface.
    - **Active/Passive:** Public IP of the secondary (floating) private IP on the Untrust interface.
    - **Active/Active:** Public IP of the Untrust interface of the firewall instance that will terminate the IPSec VPN.
3. Specify the **Vendor** to be Palo Alto.
4. Specify the **Platform/Version** to be PAN-OS 8.0.0.
5. Click on the **Create CPE** button.

    ![Click create cpe button](images/click-create-cpe-button-2.png)

    - Notice that the CPE is created with the public IP address you specified.

    ![Review created CPE](images/task-2-review-created-cpe.png)

## Task 3: Create IPSec Connection

In this task, you create the **IPSec Site-to-Site VPN connection** between the previously created DRG and CPE. This defines the OCI side of the encrypted tunnels that will securely carry traffic between the remote network (Palo Alto in Frankfurt) and OCI Milan. You will review the tunnel parameters, routing type, and shared secrets that will later be configured on the Palo Alto firewall.

1. Click on the hamburger menu in the upper left corner.
2. Click on **Networking**.
3. Click on **Site-to-Site VPN**.

    ![Open VPN service](images/task-3-open-vpn-service.png)

    - Click on the **Create IPSec connection** button.

    ![Open IPSec creation](images/task-3-open-ipsec-creation.png)

<!-- -->

1. Specify a **Name** of the IPSec connection.
2. Select the **CPE** you just created.
3. Keep the **CPE behind NAT device** option turned off.
4. Select the **DRG** where you want to terminate the tunnel on.
5. Specify the **Static routes** with the networks that are located on the remote side (OCI Frankfurt Hub VCN in this workshop).

    ![Configure IPSec connection](images/task-3-configure-ipsec-connection.png)

<!-- -->

1. Specify the **Name** for Tunnel 1.
2. Enable the switch to **Provide a custom shared secret** key, and specify the **shared secret key**.
3. Set the **IKE version** to IKEv2.

    ![Configure tunnel one](images/task-3-configure-tunnel-one.png)

<!-- -->

1. For the **Routing type** select Static routing.
2. Do not use **inside tunnel interface** IP addresses.
    - Notice that we did not assign an IP address to the tunnel interfaces. For static routing, this is optional. For BGP deployments, assigning an IP address to each tunnel interface is mandatory.
    - As stated in [Palo Alto documentation](https://docs.paloaltonetworks.com/network-security/ipsec-vpn/administration/site-to-site-vpn-quick-configs/site-to-site-vpn-with-static-routing): “With static routes, the tunnel interface doesn’t require an IP address. Traffic destined to the specified subnet automatically uses the tunnel interface as the next hop. Consider assigning an IP address if you want to enable tunnel monitoring”.

    ![Select static routing](images/task-3-select-static-routing.png)

<!-- -->

1. Open the **Advanced options** for Tunnel 1.
2. Keep the default values.

    ![Review tunnel options](images/task-3-review-tunnel-options.png)

<!-- -->

1. Open the **Phase one (ISAKMP) configuration** for Tunnel 1.
2. Enable the switch to **Set custom configurations**.
3. For the **Custom encryption algorithm** select `AES_256_CBC`.
4. For the **Custom authentication algorithm** select `SHA2_384`.
5. For the **Custom Diffie-Hellman group** select `GROUP20`.
6. For the **IKE session key lifetime in seconds** select `28800`.

    ![Configure IKE phase one](images/task-3-configure-ike-phase-one.png)

<!-- -->

1. Open the **Phase two (IPSEC) configuration** for Tunnel 1.
2. Enable the switch to **Set custom configurations**.
3. For the **Custom encryption algorithm** select `AES_256_GCM`.
4. For the **IPSEC key lifetime in seconds** select `3600`.
5. Enable the switch to **Enable perfect forward secrecy**.
6. For the **Perfect forward secrecy Diffie-Hellman group** select `GROUP5`.

    ![Configure IPSec phase two](images/task-3-configure-ipsec-phase-two.png)

    > **Note:** For the list of supported IPSec parameters and configurations, refer to the [Oracle documentation](https://docs.oracle.com/en-us/iaas/Content/Network/Reference/supportedIPsecparams.htm). In this workshop, we used the recommended values to ensure compatibility and best practice alignment.

    - **Repeat the same steps with the same settings for Tunnel 2.**
    - Click on the **Create IPSec connection** button.

    ![Click create IPSec connection button](images/click-create-ipsec-connection-button-2.png)

<!-- -->

1. Click on **Tunnels**.
2. Notice that two tunnels are created for HA. Write down both public IP addresses, as they will be used when configuring the CPE (Palo Alto) in Frankfurt region in Lab 2.

    ![Review IPSec tunnels](images/task-3-review-ipsec-tunnels.png)

    > **Note:** At this stage, the tunnels will be **Down**, because the remote-side configuration has not been completed yet. The tunnels will come **Up** after configuring the IPSec settings on the Palo Alto firewall in lab 2.

    - Click on **Tunnel 1**.

    ![Open tunnel one](images/task-3-open-tunnel-one.png)

    - You are in Tunnel 1 page.

    ![Review tunnel one](images/task-3-review-tunnel-one.png)

<!-- -->

1. Scroll down.
2. Click on the dots on the right of **Shared Secret**.
3. Click on **Edit**.

    ![Edit shared secret](images/task-3-edit-shared-secret.png)

    - This is the shared secret we provided while creating the tunnels. If you did not provide one, Oracle will generate a shared secret for you.
    - You can change it if needed; in this lab, leave it as is.
    - Write down the shared secret of each tunnel, as you will use them in Palo Alto.

    ![Review shared secret](images/task-3-review-shared-secret.png)
